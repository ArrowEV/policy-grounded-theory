# Coding Workflow

## 1. Before Coding

Read the current project state:

1. The researcher's current theory-development memo, if available.
2. The sampling decision log, if available.
3. The latest concept list and coding records.
4. Category relationships and integration outputs, if those phases have started.

Use the project's chosen locations. No specific folder structure is required.

If no prior state exists, treat the task as Iteration 0 or Pilot Coding.

## 2. Sampling Logic

Use maximum variation only for initial sampling. After Pilot Coding, use theoretical sampling.

Sampling decisions must specify:

- Which text types to sample next.
- Which empirical gap they address.
- Which theoretical puzzle they test or clarify.
- Expected contribution to the knowledge line.

Typical dimensions:

- Time stage.
- Legal effect level.
- Issuing authority.
- Policy tool type.
- Regulatory stage: ex ante, ongoing, ex post.
- Source type: institutional text or execution text.

## 3. Open Coding

For each policy text:

1. Extract document metadata: title, issuing authority, date if present, database identifier if present, source path.
2. Split into units by article, clause, item, or coherent paragraph.
3. Assign unit IDs, for example `T01-A003` or `T01-P012`.
4. Code each unit using an action-oriented label.
5. Add sensitizing guidance only as a tag, using only sensitizing concepts declared for the current study.
6. Mark `[涌现]`, `[需讨论]`, and `[理论回响：...]` where appropriate.
7. Compare each new code with prior concepts.

## 4. Axial Coding

Develop categories and relationships when the evidence supports them; no fixed concept-count threshold is prescribed. Use axial coding terminology and a paradigm model only when consistent with the selected methodological approach.

Build relationships along three dimensions:

- Tool attribute: what policy tool cluster is forming?
- Governance function: what function or mechanism is supported by the evidence?
- Temporal evolution: what phase or transition does it represent?

Use the Strauss and Corbin paradigm model only when it helps clarify:

- Conditions.
- Context.
- Actions or interactions.
- Consequences.

Do not force all policy texts into the paradigm model.

## 5. Cross-Source Mapping

This step is optional for studies with both institutional and execution sources. Only start after those sources have been independently coded. Absence from the sampled execution materials is not proof that a practice is absent in reality.

Map by functional equivalence:

- What institutional function is designed?
- What execution practice corresponds to it?
- Is the relationship convergence, divergence, or blind spot?

Look for:

- Institution designed but execution absent.
- Execution frequent but institution under-specified.
- Execution distortion, over-enforcement, under-enforcement, or symbolic compliance.
- Time-lagged institutional response to execution problems.

## 6. Selective Coding

Start when at least several main categories and their relationships are visible.

Outputs:

- Core category candidates.
- Centering test: relationship density, explanatory power, variation coverage, negative case handling.
- Storyline draft.
- Theoretical propositions.
- Boundary conditions.

Do not prescribe an expected model. Build and revise relationships from the coded evidence, including contradictions and boundary conditions.

## 7. Gap Diagnosis and Theoretical Interaction

Every round must diagnose:

- Coverage gap.
- Relationship gap.
- Variation gap.
- Negative-case gap.
- Conceptualization gap.
- Mechanism gap.
- Framework gap.

For theory interaction, state:

- The current puzzle in theoretical language.
- Relevant theories and specific concepts.
- Competing explanations.
- What text or analysis would distinguish those explanations.

Do not invent literature claims when uncertain. Ask or verify.

## 8. Saturation

Track saturation by:

- New concepts.
- New categories.
- New properties of existing categories.
- New relationships.
- New negative cases.

A category is not saturated merely because its label repeats. It is closer to saturation when new texts no longer add properties, dimensions, relationships, or boundary conditions.
