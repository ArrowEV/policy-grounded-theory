# Policy Grounded Theory · 政策文本扎根理论 Skill

**让政策条款、编码判断、理论抽样与机制解释形成可追溯的研究过程。**

Policy Grounded Theory 是面向政策文本质性研究设计的 AI Skill。它将条款切分、初始编码、持续比较、范畴发展、理论抽样、备忘录和饱和度评估组织为可以反复推进的工作流，并为同时使用制度文本与执行材料的研究提供跨源比较规则。

它关注政策文本正在做什么：设定何种义务、如何约束行为、怎样分配责任、通过什么安排推动治理行动。研究者可以沿着这些行动形成概念，比较概念之间的差异，再逐步发展范畴、关系与解释。

本 Skill 以指令、流程和记录模板支持 AI 辅助分析。研究问题、编码修订、方法选择和最终理论判断由研究者掌握。

## 为什么适合政策研究

政策研究需要同时处理文本出处、制度行动、政策差异和执行证据。本 Skill 针对这些工作设置了具体的分析规则。

| 政策研究中的任务 | 本 Skill 的设计 | 对研究过程的帮助 |
| --- | --- | --- |
| 一份文件包含多个条款，部分条款需要结合上下文理解 | 以条、款、项或语义完整段落切分；需要时保留关联条款 | 让分析单元足够具体，同时保留解释所需的上下文 |
| 概念需要返回原文核对 | 记录原文摘录、来源文件、条款位置和可用的数据库标识 | 建立从编码判断到政策证据的回查路径 |
| 研究需要解释制度如何行动 | 优先使用行动导向标签，如“设定披露义务”“明确回应期限” | 将分析推进到义务、责任、约束和治理安排的具体内容 |
| 文件来自不同时期、发文机关和效力层级 | 将时间、效力层级、发文机关、监管阶段和来源类型作为可考虑的抽样维度 | 支持有目的地寻找差异、变化和边界，而非单纯增加文件数量 |
| 研究者已有政策工具分类或理论概念 | 将其作为可修正的敏感性概念，单独记录涌现概念 | 让既有知识提供分析起点，并保留修改原有理解的空间 |
| 制度规定与执行材料的表述方式不同 | 两类来源先独立编码，再论证其功能对应关系 | 支持比较制度设计与执行实践之间的收敛、发散和盲区 |
| 多轮分析需要说明何时停止补充材料 | 追踪新概念、新范畴、新属性与维度、新关系及负例 | 为继续抽样或接近饱和的判断留下具体依据 |

这些设计可以用于政策工具、政策演化、制度执行和治理机制等研究主题。具体适用性取决于研究问题与材料；本包不绑定特定政策领域，也不预置最终的工具分类或机制模型。

## 核心能力

### 1. 从政策原文到有证据的编码

对每份文本提取标题、发文机关、日期等可用元数据，划分编码单元并分配标识，将概念与原文位置关联起来。编码记录同时保留敏感性概念、判断备注和待讨论问题，便于研究者逐项复核。

以下为虚构示例，仅用于展示记录方式：

> 第六条：有关部门应当在收到申请后十个工作日内作出答复，并保存办理记录。

| 单元 | 候选概念 | 原文依据 | 解释边界 |
| --- | --- | --- | --- |
| 示例文本—第六条 | 设定答复时限 | “十个工作日内作出答复” | 条款规定了期限；是否按期答复需要执行证据 |
| 示例文本—第六条 | 要求留存办理记录 | “保存办理记录” | 条款提出记录要求；是否形成有效追责仍需分析 |

这种记录方式使制度规定、分析解释和待验证的执行情况能够分别接受检查。

### 2. 持续比较与范畴发展

每一轮编码都要与已有分析连接，比较事件与事件、概念与概念、当前批次与既有批次。随着证据积累，整理范畴的属性、维度和关系，并保留新增、修正、合并和重复概念的记录。

关系分析可围绕政策工具属性、治理功能和时间演化展开。它们是帮助提出问题的分析方向，具体范畴与关系仍需由材料支持。

### 3. 用缺口诊断推动理论抽样

每轮分析之后，继续回答“还缺什么材料，以及为什么需要它”。工作流把抽样理由分成相互关联的几个层面：

| 诊断层面 | 需要追问的问题 |
| --- | --- |
| 经验缺口 | 材料是否遗漏重要情境、关系、变异或负例？ |
| 理论缺口 | 概念是否清楚？机制解释是否充分？整体关系是否仍有断裂？ |
| 理论互动 | 当前发现可以与哪些具体理论概念对话？有哪些竞争性解释？ |
| 抽样响应 | 下一轮应补充什么文本，才能区分这些解释或完善范畴？ |

抽样建议需要说明候选文本类型、对应缺口、理论探索目标和优先级，使后续材料收集能够回应已经出现的分析问题。

### 4. 制度与执行的双源比较

对于同时具有制度文本和执行材料的研究，本 Skill 提供一套有顺序的比较流程：

1. 分别编码制度文本和执行材料，保留各自形成的概念与证据。
2. 在范畴与关系发展阶段，分析制度功能与执行实践是否存在可论证的对应关系。
3. 整理收敛、发散和盲区，并记录两侧证据、解释与仍需补充的材料。

| 比较方向 | 可提出的研究问题 |
| --- | --- |
| 收敛 | 执行实践如何体现制度设计中的功能？这种对应在什么情境下成立？ |
| 发散 | 实践与制度设计在哪些方面出现偏离？有哪些可能的解释？ |
| 盲区 | 一侧出现的重要安排或实践，在另一侧是否缺少对应证据或明确规定？ |

对应关系依据功能和证据论证，不能仅凭标签相同建立。执行材料中没有观察到某种实践，也不能直接断言现实中不存在该实践。

单一来源研究可以直接跳过这一模块。

### 5. 备忘录与知识线更新

每轮分析记录核心范畴候选、故事线草稿、理论对话进展和当前尚未解决的问题，形成可以在下一轮继续读取的研究状态。

“知识线”记录的是研究理解如何变化：哪些概念被保留或修改，哪些解释得到支持，什么负例迫使研究者重新考虑范畴，以及下一轮为什么转向某类材料。已有项目可以沿用自己的目录和记录方式，无需迁移到固定的个人文件结构。

### 6. 核心范畴与理论整合

当主要范畴及其关系逐渐清晰时，支持提出核心范畴候选、组织故事线、形成理论命题并说明边界条件。候选核心范畴需要结合关系密度、解释力、变异覆盖和负例处理情况接受检查。

工作流不事先规定一个必须得到的模型。新的证据可以推动研究者重新编码、调整范畴，或修改已经形成的解释。

### 7. 多维度饱和度追踪

饱和度评估同时关注新概念、新范畴、既有范畴的新属性与维度、新关系和新负例。标签重复只是观察的一部分，还需要检查后续材料是否继续改变范畴的内涵及适用边界。

输出需要指出哪些范畴接近饱和、哪些仍需补充证据，以及停止或继续抽样的理由。

## 贯穿流程的设计优势

**证据与解释保持关联。** 原文、单元位置、概念、范畴关系和抽样理由都有相应的记录位置，方便研究者回查和说明分析过程。

**每轮分析都有下一步。** 编码结果会连接到缺口诊断、竞争性解释和理论抽样，帮助研究从材料整理继续走向解释发展。

**为意外发现留出位置。** `[涌现]` 用于标记超出当前敏感性概念的发现；`[需讨论]` 用于保留尚不能确定的判断；有依据的理论联系可标记为 `[理论回响：理论名-概念名]`。

**允许返回与修正。** 范畴发展、理论整合和饱和度检查都可以促使研究回到原文或补充材料，适合多轮推进的研究过程。

**流程与输出配套。** 指令之外提供中文编码表、抽样诊断表、关系矩阵、跨源映射表和饱和度追踪表，让分析决策能够形成可编辑的记录。

以上是现有工作流的设计特点，尚不代表经过实证比较的准确率或效率优势。

## 如何推进一项研究

```text
研究问题、方法取向与材料范围
            ↓
      试编码与初始概念
            ↓
   持续比较、范畴与关系发展
            ↓
  经验缺口、理论缺口与竞争性解释
            ↓
   理论抽样 → 补充材料 → 返回编码
            ↓
   核心范畴、故事线与边界条件
            ↓
      饱和度评估与研究者判断
```

制度与执行双源比较可在两侧独立编码后接入范畴与关系分析。备忘录和知识线记录贯穿各轮。

## 可以得到哪些输出

| 分析任务 | 主要输出 |
| --- | --- |
| 初始/开放编码 | 文本元数据、编码单元切分表、开放编码表、本批概念变化摘要、初步理论观察 |
| 范畴与关系整理 | 范畴聚合表、属性与维度、关系矩阵、敏感性概念与涌现范畴比较 |
| 理论抽样 | 经验与理论缺口、理论互动诊断、竞争性解释、下一轮抽样建议 |
| 双源比较 | 功能对应矩阵、收敛—发散—盲区记录、跨源理论洞察 |
| 理论整合 | 核心范畴候选、故事线草稿、理论命题、负例与边界条件 |
| 过程记录 | 分析备忘录、抽样决策、知识线更新、待讨论问题 |
| 饱和度评估 | 多轮追踪表、范畴饱和判断、仍需补充的证据及停止/继续理由 |

模板按任务选择使用。试编码可以先产出少量可复核记录，无需一次完成所有阶段。

## 快速开始

### 安装

将本仓库放入所用工具的 skill 目录，保留 `SKILL.md`、`references/` 与 `evals/` 的相对位置。以 Codex 的常用安装位置为例：

```bash
git clone https://github.com/ArrowEV/policy-grounded-theory.git \
  ~/.codex/skills/policy-grounded-theory
```

如果该目录已经存在，请先检查已有内容，避免覆盖自己的定制版本。其他支持 `SKILL.md` 的工具使用各自的安装位置；具体调用方式以宿主工具为准。

本包无需安装其他通用扎根理论 skill，也没有额外的 Python 包依赖。

### 提供研究上下文

开始时提供研究问题、政策文本、方法取向和已有分析状态即可。可以直接粘贴文本，也可以在宿主工具支持读取文件时提供材料位置。

多轮研究应同时提供或允许读取已有编码、备忘录及抽样日志，帮助下一轮延续此前的概念与判断。

### 示例请求

**试编码**

```text
使用 $policy-grounded-theory 对以下政策文本进行试编码。
研究问题：[填写问题]
方法取向：[填写；尚未确定时先讨论]
请保留原文和条款位置，使用行动导向概念标签，
区分证据、解释与待讨论判断，并给出下一轮抽样建议。
```

**根据已有编码继续抽样**

```text
使用 $policy-grounded-theory 阅读已有编码和理论备忘录。
请诊断经验缺口、理论缺口及竞争性解释，
说明下一轮需要补充哪些文本、为什么补充，以及预期澄清什么问题。
```

**制度与执行比较**

```text
使用 $policy-grounded-theory 比较两组已独立完成编码的材料。
请论证制度功能与执行实践之间的对应关系，
整理收敛、发散和盲区，保留两侧证据并指出待验证的解释。
```

**饱和度评估**

```text
使用 $policy-grounded-theory 检查连续几轮的编码与范畴变化。
请结合属性、维度、关系和负例判断各范畴的饱和状态，
给出继续或停止抽样的理由，明确仍缺少的证据。
```

## 方法取向与使用边界

研究者可以指定方法取向。未指定时，本 Skill 以 Charmaz 建构主义取向作为工作起点，并要求明确说明这一选择。若使用 Strauss 与 Corbin 的主轴编码范式，需要解释其用途及与所选取向的关系；本工具不将不同流派视为完全相同的方法。

本包提供 AI 分析指令与模板。文件读取、网络查询、保存和上下文容量取决于宿主工具；自动采集、OCR、数据库连接及定量模型不属于本包内置功能。

编码、跨源映射和机制解释需要研究者复核。条款规定不能直接证明执行效果，文本关系也不能自动确立因果关系。不熟悉的理论、政策背景和文献主张应核实或讨论。

`evals/evals.json` 提供四类人工评估场景，覆盖开放编码、理论抽样、双源映射和饱和度判断。这些用例用于检查行为，当前不代表已完成独立行为评估或性能验证。
